起因

公司电脑，Docker Desktop 用不了——不是装不上，是不合规。Docker Desktop 走 Docker Subscription Service Agreement 授权，免费范围只有个人使用、教育、非商业开源，以及员工少于 250 人且年营收低于 1000 万美元的小型企业；公司规模过了这条线，商业使用就得买订阅，政府单位同理。走采购流程麻烦，而且它本来就是个本地开发工具，不值得。

机器内存也只有 16 GiB，Docker Desktop 那套常驻 GUI 加后台进程的开销，实话说有点浪费。

所以需求很明确：

  1. 免费，且公司商业使用也不违规
  2. 资源占用小，16 GiB 的机器得留够内存给 IDE 和浏览器
  3. 性能要好，构建和文件挂载不能拖后腿
  4. 原生兼容 docker 和 docker compose 命令，不想改脚本、改 CI

选型：几个方案摆一起看

方案 授权 原生 docker/compose 资源占用 结论
Docker Desktop 大企业商业使用需付费 是 重（GUI + 常驻进程） 授权不合规，排除
OrbStack 公司/商业使用需按人购买 是 很轻 性能最好，但要钱，排除
Rancher Desktop Apache-2.0，免费 可切到 moby（dockerd） 中（Electron GUI） 可用，GUI 偏重
Podman Apache-2.0，免费 否，命令是 podman / podman compose 轻 免费但兼容性打折
Colima MIT，完全免费 是（跑的就是 dockerd） 轻（纯 CLI） 选它

逐个说下排除理由。

Docker Desktop 是默认答案，兼容性最好，但在公司场景直接卡在授权上。

OrbStack 是这几个里性能最强的，启动快、占用低，但它同样不是免费的。官方授权页写得很清楚：freelancer、商业或非营利实体、政府实体，或者与 OrbStack 相关的工作年收入超过 1 万美元，都必须按用户购买授权；装完只有 30 天 Pro 试用，试用结束降级为"个人使用"。所以公司电脑上它和 Docker Desktop 是同一个问题。

Rancher Desktop 是 SUSE 开源的（Apache-2.0），免费，功能也全，内置 k3s，运行时能在 moby（dockerd）和 containerd 之间切。代价是它是个 Electron 桌面应用，GUI 和常驻开销比纯 CLI 方案大，对 16 GiB 的机器不算友好。

Podman 完全免费，无守护进程、rootless，安全性也好。问题是它的命令叫 podman 而不是 docker，compose 也是 podman compose，背后还要另装 provider。虽然可以配 alias 或 socket 兼容层，但"原生兼容"这条就打了折——团队脚本、CI、文档里全是 docker xxx，我不想在这上面花精力。

Colima 正好卡在这几条需求的交集上：MIT 协议，公司用也不违规；纯 CLI，没有 GUI 常驻进程；而且它不是"模拟" docker——它就是在虚拟机里跑了一个真的 dockerd，把 socket 暴露给宿主机，所以 docker 和 docker compose 完全原生，一个命令都不用改。

Colima 是什么

Colima 是 Containers on Lima 的缩写。它在 macOS 上借 Lima 起一个轻量 Linux 虚拟机，虚拟机里跑 dockerd，再把 Docker socket 暴露给宿主机的 docker 命令。

1
2

macOS 主机                          Colima 虚拟机
docker CLI / docker compose ─socket─▶ dockerd / 容器 / 镜像

除了 Docker，运行时还能选 containerd（配 nerdctl）或 incus，顺手也能起一套 k3s。

安装

1

brew install colima docker docker-compose docker-buildx

四个包各管一摊：

  • colima：管理器，依赖 lima
  • docker：只装 CLI，不带 daemon——这正是关键
  • docker-compose：Compose v2
  • docker-buildx：构建插件，brew install docker 不会带上它，得单独装

创建虚拟机：这条命令就是全部

我创建时只用了这一条：

1

colima start --cpu 4 --memory 8 --disk 60

跟默认值对比，真正被我改掉的只有三项：

配置项 默认 我设的
cpu 2 4
memory 2 8
disk 100 60

其余全是默认值。vmType: vz（Apple 的虚拟化框架）、mountType: virtiofs（最快的挂载驱动）、binfmt: true（能直接跑 amd64 镜像）在 Apple Silicon + macOS 13 以上本来就是默认，所以命令行里不用写。

参数怎么给，几点经验：

  • CPU：默认 2 核偏少，给 4 核，编译和并行跑容器都从容。
  • 内存：默认 2 GiB 基本不够用，跑两个容器就开始吃紧。但别照抄 8 GiB——16 GiB 的机器分走一半后宿主机只剩 8 GiB，IDE 一开就紧张，建议给 4~6 GiB，把内存留给宿主机。
  • 磁盘：默认 100 GiB，我设了 60。磁盘只能调大不能调小，官方注释写得很直白（value can only be increased after virtual machine has been created），所以一开始宁可给宽一点。

有个细节要提醒：我这份配置里 disk 写的是 60，但进虚拟机看实际设备是 100 GiB：

因为磁盘只支持扩容、不支持缩容——--disk 如果是在虚拟机建好之后才补上的，它不会真的把盘改小。所以磁盘大小最好创建时一次定好，或者干脆别省，直接用默认的 100。

有些配置没法用命令行参数表达，比如 dockerd 的 daemon 配置、provision 脚本。这种情况用：

1

colima start --edit

它会打开 yaml，改完保存再启动。也可以直接编辑 ~/.colima/default/colima.yaml，下次 start 生效。

docker compose 用不了，怎么办

装完 docker run 是好的，但 docker compose（带空格那个）会直接报错：

1
2
3

$ docker compose version
docker: unknown command: docker compose
Run 'docker --help' for more information

原因是 brew 装的 docker-compose 是 Docker CLI 的插件，它被放在 Homebrew 自己的插件目录里（$(brew --prefix)/lib/docker/cli-plugins），而 Docker CLI 默认不会去那里找。

最省事：直接用 docker-compose

1
2

$ docker-compose version
Docker Compose version 5.5.1

就是命令名多了个连字符，别的没差别。我比对过两者的 md5——brew 在插件目录里放的那个 docker-compose，本身就是指向 bin/docker-compose 的软链，同一个二进制、同一个版本：

1
2
3
4

$ md5 -q /opt/homebrew/Cellar/docker-compose/5.5.1/bin/docker-compose
dccdcf38cd7fff7f229d3a1748b74126
$ md5 -q /opt/homebrew/Cellar/docker-compose/5.5.1/lib/docker/cli-plugins/docker-compose
dccdcf38cd7fff7f229d3a1748b74126

所以它不是"旧版 Compose v1"，就是正牌的 Compose v2：

  • 功能完全一致，up / down / build / logs 一个不少
  • 配置文件也完全通用，docker-compose.yaml、docker-compose.yml、compose.yaml、compose.yml 都能识别，内容格式一模一样
  • 现有脚本只要把 docker compose xxx 改成 docker-compose xxx 就能跑

不配任何东西就能用，我一开始就是这么用的。

如果确实要用带空格的 docker compose

团队里都在敲 docker compose、或者不想改脚本的话，把它注册成插件就行。两种方式我都实测过，都能生效。

方式一，告诉 Docker CLI 去 Homebrew 的插件目录找（Homebrew 官方推荐）：

1
2
3
4
5
6
7

{
	"auths": {},
	"currentContext": "colima",
	"cliPluginsExtraDirs": [
		"/opt/homebrew/lib/docker/cli-plugins"
	]
}

注意是往已有的 ~/.docker/config.json 里加一个字段，别整个覆盖。Apple Silicon 的 brew 前缀是 /opt/homebrew，Intel 机器是 /usr/local，用 brew --prefix 确认一下。

方式二，软链到用户级插件目录：

1
2

mkdir -p ~/.docker/cli-plugins
ln -sfn /opt/homebrew/opt/docker-compose/bin/docker-compose ~/.docker/cli-plugins/docker-compose

改完验证：

1
2

$ docker compose version
Docker Compose version 5.5.1

这一步不是必须的——不做也能用 docker-compose 正常干活，功能没有任何差别。我平时就是直接用 docker-compose。

日常用法

起停和状态

1
2
3
4
5

colima start
colima stop
colima restart
colima status
colima list        # 别名 ls

彻底删掉重来：

1

colima delete --data --force

--data 连镜像和容器一起清，--force 跳过确认。这两个一起用之前心里要有数，删了就真没了。

改资源

只能先停再改：

1
2

colima stop
colima start --cpu 6 --memory 12

CPU 和内存随便调，磁盘只能往上加。

挂载目录

默认会把 $HOME 和 /tmp/colima 挂进去，容器里能直接访问你的代码目录。要额外挂别的：

1

colima start --mount ~/work:w     # :w 表示可写

我平时用默认的就够。

端口和网络

容器映射到宿主机的端口默认就能访问，不用额外配。要让虚拟机在局域网里有独立 IP：

1

colima start --network-address

国内网络可能需要指定 DNS：

1

colima start --dns 223.5.5.5 --dns 1.1.1.1

多套环境用 profile

想同时跑两套互不干扰的环境，用 profile：

1
2
3
4

colima start --profile dev  --cpu 2 --memory 4
colima start --profile test --runtime containerd
colima list
colima stop --profile dev

每个 profile 是独立的虚拟机和 socket。

换 containerd + nerdctl

1
2
3

colima start --runtime containerd
colima nerdctl install
nerdctl run hello-world

顺手起个 k3s

1
2
3

brew install kubectl
colima start --kubernetes
kubectl get nodes

管理命令：colima kubernetes start|stop|reset|delete。

进虚拟机

1
2

colima ssh
colima ssh -- htop     # 直接执行命令

踩坑记录

docker compose 用不了 —— 前面说过。直接用 docker-compose 就行，两者是同一个二进制；想用带空格的，按上面注册插件。

Cannot connect to the Docker daemon —— 十有八九是虚拟机没起来，或者 context 跑偏：

1
2

colima status
docker context use colima

起不来，报虚拟化相关的错 —— 换个 VM 类型试试：

1
2

colima start --vm-type vz      # Apple Silicon 默认，最快
colima start --vm-type qemu    # 兼容性更好，慢一些

挂载的文件改了容器里不更新 —— 开一下 inotify：

1

colima start --mount-inotify

卸载

1
2
3

colima stop
colima delete -f
brew uninstall colima docker docker-compose docker-buildx

最后

换成 Colima 之后，docker 命令照旧，compose 用 docker-compose（或者按上面的方式注册一下，让 docker compose 也能用），公司合规问题没了，机器上也少了一个常驻的 GUI 应用。

16 GiB 的机器上，把内存参数往下调一点、CPU 给 4 核，日常开发完全够用。团队用的话，把 colima.yaml 一起提交，新同事 clone 下来 colima start --edit 就能对齐环境，省得口头描述配置。
