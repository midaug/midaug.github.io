算法说明

怎么用：下载大文件后，去发布页找到官方的校验值，粘贴到「校验比对」里 —— 只要有一个算法对上， 就说明文件与官方发布的一致、没有被中间环节篡改或截断。
为什么现在推荐 SHA-256：MD5 与 SHA-1 都已被证实存在碰撞攻击（能造出两个内容不同但摘要相同的文件）， 做完整性校验已经不够安全，只适合当「内容指纹」用来去重。SHA-2 系列目前没有已知的实用碰撞攻击。
HMAC 和普通哈希的区别：普通哈希谁都能算，所以「摘要正确」不能证明「来源可信」； HMAC 把密钥混进计算过程，只有持有密钥的一方能生成或验证，因此可以用来做 API 签名。
CRC32 不是加密哈希：它只是传输检错码，用来发现随机比特翻转，任何人都能轻易伪造。 本工具里放在一起只是为了顺手，不要拿它当安全校验。
